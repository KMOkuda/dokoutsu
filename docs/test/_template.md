# テスト仕様書: (画面名)

> 画面単位で1ファイル作成する。
> 配置: `docs/test/(画面コード)_(画面名).md`
> 対応する詳細設計書: `docs/design/(画面コード)_(画面名).md`

---

## 書き方のきまり

- 各ケースの表の「設計書」列には、根拠となる詳細設計書の章番号を書く(例: `3.2`、`4.1`)。エラーケースは`5(番号)`と書く(例: `5(8)`)。基本設計書が根拠の場合は`基本3.3`のように書く
- 期待結果・操作は、その行だけ読んで分かるように全文を書く(「同上」を使わない)
- エラーメッセージは、詳細設計書「5. エラーケース」の文言を全文そのまま書く
- 用語(ボタン名・画面名)は詳細設計書の表記に合わせる
- ケース番号の記号は、全ての仕様書で次の意味に統一する。該当するケースがない章は設けない

| 記号 | 章 | 内容 |
|---|---|---|
| N | 正常系 | 詳細設計書「3. 処理の流れ」「2.4 画面遷移」の正常な動作 |
| E | 異常系 | 詳細設計書「5. エラーケース」 |
| A | 権限・アクセス制御 | 詳細設計書「6. セキュリティ上の考慮点」 |
| V | 入力値の検証 | 文字数・形式などの入力チェック |
| B | 送信ボタンの活性条件 | 詳細設計書「4.1 UI要素の動作」の活性条件 |
| D | 表示・操作 | 表示内容・並び順・初期値・画面上の操作 |
| K | リンクの有効期限 | メールで送るリンクの有効期限・改ざん |
| P | 回答投稿の頻度制限 | 基本設計書「3.3 回答投稿の頻度制限」 |
| O | 1問題1回答 | 同じブラウザからの回答を1回に限る動作 |
| R | 未確認アカウントへの再登録 | 確認前のアカウントへの登録し直し |
| L | メール送信回数の制限 | 基本設計書「3.2 メール送信回数の制限」 |
| C | 共通 | 特定の画面に属さない動作(`00_共通.md`のみ) |

- 章は上の表の順に並べ、最後の章を「対応状況」にする
- 「対応状況」のテストメソッドは`クラス名.メソッド名`で書く。E2Eで確認するケースは`E2E E3(test_…)`のように、E2E仕様書のフローNoとメソッド名を書く。1つのテストで一部だけを確認する場合などの補足は「備考」列に書く
