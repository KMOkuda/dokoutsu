# 詳細設計書: 共通メニュー

---

## 1. 概要

| 項目 | 内容 |
|---|---|
| 画面コード | M |
| URL | 該当なし(各画面のヘッダーに組み込む共通コンポーネント) |
| HTTPメソッド | 該当なし |
| 対応要件 | 画面遷移の共通導線(個別の機能要件には対応しない) |
| ログイン | 必須(ログイン後の画面でのみ表示) |
| 使用モデル | 該当なし |
| テンプレート | components/menu.html(各テンプレートからinclude) |
| 実装優先度 | 高 |
| デザイン参考 | docs/design/screens_wireframe/M_共通メニュー_design.pdf |

> ログイン中の場合のみ、画面を問わずヘッダーに表示する。未ログインの場合は表示しない
> (回答投稿画面・回答一覧画面はログイン不要で到達できるが、ログイン中であれば表示する)。
> 基本設計書「4.3 共通メニュー」を参照。

## 3. 処理の流れ

### 3.1 初期表示時 (GET)

1. ヘッダーのメニューアイコンは常に表示する(メニュー本体は閉じた状態)

### 3.2 送信時 (POST)

該当なし(ログアウトリンクのみDjango標準のログアウト処理を呼び出す)

---

## 4. 画面構成

### 4.1 UI要素の動作

| 要素 | 種類 | 動作 | 活性条件 |
|---|---|---|---|
| メニューアイコン | ボタン | メニューを開く(オーバーレイ表示) | 常時活性 |
| 閉じるボタン | ボタン | メニューを閉じる | メニュー表示中のみ |
| 各メニュー項目リンク | リンク | 対応する画面へ遷移する | 常時活性 |

### 4.2 レイアウトの制約

| 項目 | 内容 |
|---|---|
| 表示位置 | ヘッダー右上のアイコンから開くオーバーレイ |
| 可変・固定 | オーバーレイは画面上に重ねて表示し、背後の画面はスクロールを止める |
| その他 | 各画面のヘッダーで共通のコンポーネントとしてincludeする(画面ごとに個別実装しない) |
