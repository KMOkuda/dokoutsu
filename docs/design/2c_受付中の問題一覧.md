## 3. 処理の流れ

### 3.1 初期表示時 (GET)

1. ログイン中のユーザーのProblemのうち、deadline未経過かつclosed_atが未設定のものを、締切が近い順に取得する
2. 各Problemの回答数を集計する
3. 該当するProblemが0件の場合、空の状態の案内を表示する

### 3.2 送信時 (POST)

**出題を終了する**

1. 対象ProblemのIDを受け取る
2. 対象Problemがログイン中のユーザーのものであることを確認する
3. closed_atに現在時刻を設定する
4. 一覧を再取得し、対象カードは受付終了の問題一覧側に移る

**問題を削除する**

1. 対象ProblemのIDを受け取る
2. 対象Problemがログイン中のユーザーのものであることを確認する
3. Problemを削除する。ON DELETE CASCADEにより、紐づくAnswerPostも合わせて削除される
4. 一覧を再取得する

## 4. 画面構成

### 4.1 UI要素の動作

| 要素 | 種類 | 動作 | 活性・表示条件 |
|---|---|---|---|
| 問題ボタン | ボタン | 回答投稿画面へ遷移する | 常時活性 |
| 回答 Nボタン | ボタン | 回答一覧画面へ遷移する。Nは回答数 | 常時活性 |
| 「…」ボタン | ボタン | 操作ボトムシート(出題を終了する/問題を削除する/キャンセル)を開く。見出しに「手番／タイトル」と「回答N件・受付中」を表示する | 常時活性 |
| ボトムシート内「出題を終了する」 | ボタン | 終了確認ダイアログを開く | 常時活性 |
| ボトムシート内「問題を削除する」 | ボタン | 削除確認ダイアログを開く | 常時活性 |
| 終了確認ダイアログ内「出題を終了する」 | ボタン | closed_atを更新する | 常時活性。送信中(押してから次の画面が表示されるまで)は非活性 |
| 削除確認ダイアログ内「削除する」 | ボタン | Problemを削除する | 常時活性。送信中(押してから次の画面が表示されるまで)は非活性 |
| シェアボタン | ボタン | シェアシート(LINE・X・メール・リンク・他のアプリでシェア)を開く | 常時活性 |

### 4.2 レイアウトの制約

| 項目 | 内容 |
|---|---|
| 表示順 | 締切が近い順に上から並べる |
| 可変・固定 | カード一覧は縦スクロールで可変 |
| その他 | 空の場合はカード一覧の代わりに案内文と導線を表示する |

|---|---|---|---|---|
