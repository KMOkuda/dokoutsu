# 指示・修正要望ログの運用

## 目的

同じ種類の指摘を繰り返し受けることを防ぐ。
過去に受けた指示を蓄積し、次回以降は指摘される前に反映する。

## 記録先

`docs/instruction_log.md`

---

## 記録するタイミング

以下を受けたとき、作業を完了した後に追記する。

- ドキュメント・コードの修正要望
- レビューでの指摘
- 方針の変更・決定
- 「〜しないで」「〜してほしい」という形の指示

## 記録しないもの

- 単なる質問(「〜とは何か」)
- 情報提供の依頼(「〜を調べて」)
- 記録済みの指示と同一内容のもの(既存項目に日付を追記する)

---

## 記録の形式

```markdown
## YYYY-MM-DD

### 対象: (ドキュメント名 / コード / 全般)

- **指示**: (受けた指示を一文で)
- **背景**: (なぜそう指示されたか。分かる範囲で)
- **対応**: (実際に何をしたか)
```

---

## 作業前の確認

以下の作業を始める前に、`docs/instruction_log.md` を読み、
過去に同種の指示を受けていないか確認する。

- ドキュメントの新規作成・大幅な修正
- 実装(コードの新規作成)
- レビュー

過去の指示に該当する内容があれば、指摘される前に反映する。

**「→ (昇格先)へ昇格済み」と記載済みの項目は読み飛ばしてよい。**
昇格済みの内容は該当するSKILL.mdに移動済みで、そちらが作業時に自動的に参照されるため、
ログ側を読む必要があるのは未昇格の項目のみ。画面数が増えてログが肥大化しても、
確認対象が増え続けないようにするための措置。

---

## SKILL.mdへの昇格

同じ種類の指示が3回以上繰り返された場合、恒久的なルールとして
該当するSKILL.mdに追記することを提案する。

昇格先の例:

| 指示の種類 | 昇格先 |
|---|---|
| 要件定義書の書き方 | `.claude/skills/requirements-writing/SKILL.md` |
| 基本設計書の書き方 | `.claude/skills/basic-design-writing/SKILL.md` |
| コードの書き方 | `.claude/skills/coding-guideline/SKILL.md` |
| レビューの観点 | `.claude/skills/review-guideline/SKILL.md` |
| テストの書き方・観点 | `.claude/skills/testing-guideline/SKILL.md` |
| 説明の仕方・スキルレベル | `.claude/skills/explain-for-skill-level/SKILL.md` |

昇格した場合、ログ側の該当項目に「→ (昇格先)へ昇格済み」と追記する。

---

## 注意

- ログが肥大化しても、古い項目を削除しない(判断の経緯が失われるため)
- 昇格済みの項目も残す(なぜそのルールができたかの根拠になる)
